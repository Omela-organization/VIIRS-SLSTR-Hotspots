# Модули M0-M11

ТЗ v7 задаёт роли и общий порядок модулей M0–M11. В репозитории есть каталог `viirs_slstr_hotspots/pipline` с файлами `m00_load.py`–`m11_events.py`, которые пока являются заглушками. Переименование `pipline` в `pipeline` не согласовано (CQ-03).

Таблица ниже суммирует назначение модулей по ТЗ. Это не готовые Python-сигнатуры: единый формат передачи между модулями не согласован (CQ-08), а рабочие реализации шагов ещё отсутствуют.

## M0 — загрузка данных

- Назначение: загрузка исходных данных и геопривязки.
- Вход: географический полигон, интервал времени и источники данных.
- Выход: исходные файлы, геопривязка, маска облаков, СХК, манифест.
- Обязательные поля манифеста из старого документа: имя файла, версия обработки, контрольная сумма, время загрузки — PROPOSED.
- Отсутствие входных данных: неполный набор нельзя молча считать полноценным — TBD точная реакция.
- Ошибки: получение данных, неполный набор, чтение продукта, контрольная сумма.
- Task ID: TBD в отсутствие `Tasks_v3.xlsx`.

## M1 — радиометрия и геометрия

- Назначение: преобразование радиометрических данных и геометрии.
- Вход: L1B, геопривязка, СХК.
- Выход: температура, яркость, отражения, углы и площади.
- Единицы по ТЗ v7: температура K; яркость Вт·м⁻²·ср⁻¹·мкм⁻¹; углы в градусах; площадь м².
- Отсутствие СХК/геопривязки: конкретный режим ошибки или сокращённой обработки — TBD.
- Ошибки: отсутствует СХК, неизвестный канал, некорректная геопривязка, несогласованные размерности.
- Task ID: TBD.

## M2 — маски качества

- Назначение: формирование маски годности и общей маски `flags`.
- Вход: массивы M1 и флаги качества L1B.
- Выход: маска годности и `flags uint32`.
- Обязательные признаки из старого документа: `saturated`, `folded`, `mixed_saturation`, `f1_overshoot`, `bowtie_duplicate`.
- Насыщение не должно автоматически исключать кандидатов — статус TBD до сверки с ТЗ.
- Отсутствие входных флагов: TBD.
- Task ID: TBD.

## M3 — облака, снег, вода, лес

- Назначение: классификация служебных поверхностных масок.
- Вход: M1, маски M2, готовые маски облачности, опорные поля.
- Выход: облака, снег, вода, лес и соответствующие флаги.
- Поведение отсутствующих масок: старый документ предлагал `forest_unknown`; точный интерфейс TBD.
- Task ID: TBD.

## M4 — пространственный фон

- Назначение: оценка локального радиометрического фона.
- Вход: M1-M3 и геометрия.
- Выход: блочный и оконный фон, остатки, масштаб шума и рычаг h.
- Флаги из старого документа: `bg_undefined`, `crowded_window`.
- Недостаточно пикселей: выход и кодирование ошибки — TBD.
- Task ID: TBD.

## M5 — многолетний фон

- Назначение: накопление сезонной и пространственной истории фона.
- Вход: остатки M4, история, страты, месяц года, рабочая ячейка.
- Выход: медиана остатка b, масштаб q, число наблюдений n, нормированный остаток z.
- Хранение старого документа: Zarr на сетке 375 м.
- Недоступен архив: старый документ описывает холодный старт; точные параметры и выходы — TBD.
- Task ID: TBD.

## M6 — статистическое обнаружение

- Назначение: вычисление статистического решения a contrario.
- Вход: z, страты, число проверок, параметры решения.
- Выход: p-value, три NFA, significance, порог, кандидаты.
- Отсутствие достаточной выборки хвоста: точная реакция — TBD.
- Task ID: TBD.

## M7 — отбраковка ложных срабатываний

- Назначение: отбор физических/повторяющихся источников.
- Вход: M6, M1, повторяющиеся источники, геометрия и маски.
- Выход: решение; дополнительные флаги; `source_class`.
- Допустимые решения по таблице обнаружений ТЗ v7: `confirmed`, `needs_confirmation`, `rejected`.
- Классы источников по таблице обнаружений ТЗ v7: `vegetation_fire`, `persistent_industrial`, `persistent_natural_candidate`, `recurrent_seasonal`, `volcano_candidate`, `unknown`.
- Task ID: TBD.

## M8 — подтверждение повторными наблюдениями

- Назначение: агрегирование результатов во временном окне.
- Вход: остатки z нескольких пролётов, окно, информация о ясных/пропущенных наблюдениях, M7.
- Выход: обновлённое решение кандидата.
- Отсутствие наблюдения и ясное наблюдение должны различаться — TBD точная схема.
- Task ID: TBD.

## M9 — характеристики очага

- Назначение: расчёт FRP и характеристик обнаружения.
- Вход: обнаружения, фоны M4/M5, площади, радиометрия и геометрия.
- Выход: `frp_mw`, `frp_err_mw`, `frp_toa_mw`, `frp_50_mw`, POD.
- Единицы FRP по таблице обнаружений ТЗ v7: МВт.
- Task ID: TBD.

## M10 — сведение к единой сетке

- Назначение: перенос пролётов на рабочую сетку и выдачу на эталонную сетку.
- Вход: поля пролёта, обнаружения, следы пикселей, эталонная сетка, кригинг-модель.
- Выход: тензоры X и D.
- Требования к переносу на сетки и сохранению характеристик очага должны реализовываться по ТЗ; модуль и критерии приёмки пока не реализованы.
- Без кригинга: резервный режим и формат его описания требуют отдельного контракта.
- Task ID: TBD.

## M11 — события

- Назначение: объединение обнаружений в события.
- Вход: обнаружения всех пролётов, времени, геометрия, решения M7/M8, FRP/POD M9.
- Выход: таблица событий GeoParquet.
- ТЗ v7, раздел 3.2, перечисляет идентификатор и время события, статистику обнаружений, геометрию, лесную долю, FRP/FRE, качество покрытия наблюдениями, значимость и класс источника.

- Task ID: TBD.

| M6 → M7 | кандидаты и статистические признаки | Логический поток; Python API не определён |
