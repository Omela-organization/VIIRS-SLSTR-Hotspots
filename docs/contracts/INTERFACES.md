## 1. Назначение проекта

Проект предназначен для обнаружения и обработки потенциальных очагов возгорания по спутниковым данным VIIRS и Sentinel-3 SLSTR.

Назначение соответствует ТЗ v7. Текущая реализация находится на стадии каркаса и не выполняет полный цикл обнаружения.

## 2. Архитектура

Система организована как последовательный конвейер M0-M11:

| Модуль | Назначение |
|---|---|
| M0 | загрузка данных |
| M1 | радиометрия и геометрия |
| M2 | маски качества |
| M3 | облака, снег, вода, лес |
| M4 | пространственный фон |
| M5 | многолетний фон |
| M6 | статистическое обнаружение |
| M7 | отбраковка ложных срабатываний |
| M8 | подтверждение повторными наблюдениями |
| M9 | характеристики очага |
| M10 | сведение к единой сетке |
| M11 | формирование событий |

Обработка выполняется по пролётам спутника. Подробности ответственности модулей приведены в [MODULES.md](MODULES.md).

ТЗ v7 описывает конвейер M0–M11. В репозитории каталоги шагов содержат заглушки; таблица не является описанием готовых Python API.

## 3. Общая схема обработки

ТЗ v7 описывает следующий общий поток:

```text
M0 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6
 -> M7 -> M8 -> M9 -> M10 -> M11
```

Дополнительные связи и форматы передачи не считаются подтверждёнными до согласования единого контекста или схемы передачи данных.

Порядок обозначает этапы обработки, а не утверждённые форматы передачи данных между ними.

## 4. Геометрии

В ТЗ v7 описаны:

- геометрия полосы обзора;
- рабочая сетка 375 м;
- эталонная сетка 240 м.

Для таблиц обнаружений ТЗ указывает WGS 84 (EPSG:4326). Конкретные CRS рабочей и эталонной сеток, а также геометрии полосы остаются открытыми (CQ-10).

Геометрические требования и нерешённые вопросы описаны в [DATA_FORMATS.md](DATA_FORMATS.md) и [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).

## 5. Общие правила данных

- Для таблицы обнаружений ТЗ v7 задаёт float32 для измерений, float64 для координат, uint32 для флагов и uint64 для `det_id`. Точные физические типы остальных целочисленных полей требуют уточнения.
- Основные оси полосы: `line`, `sample`.
- Основные оси сетки: `y`, `x`.
- Возможные временные оси: `t`, `day`.
- Ноль не используется как универсальный признак пропуска. Числовые поля модели HS-01 отклоняют `NaN` и бесконечность.
- Для HS-01 nullable только `event_id`, `b_hist` и `q_hist`; правила истории приведены в [JSON_CONTRACT.md](JSON_CONTRACT.md).
- Рабочие размеры гранул не должны быть жёстко зашиты в исходный код.

Полные правила и неизвестные параметры приведены в [DATA_FORMATS.md](DATA_FORMATS.md).

Правила для массивов, отсутствующих значений и GeoParquet приведены в [DATA_FORMATS.md](DATA_FORMATS.md). Неописанные форматы не считаются согласованными.

## 6. Связи модулей

Точный формат передачи данных между соседними модулями не закреплён. `Runner` передаёт шагам `cfg`, `inputs`, `outputs`, `journal` и `quality`; пути в `inputs` и `outputs` ведут к JSON-файлам. Это интерфейс каркаса, а не согласованная схема содержимого данных. Модули M0–M11 пока не вызывают `validate_detection_record()`.

Каталог в коде называется `pipline`; вопрос о переименовании в `pipeline` остаётся открытым (CQ-03). Переименование не выполнялось.

- [ERRORS.md](ERRORS.md) — обработка ошибок;

## 7. Общие правила разработки

- Перед началом Task ID изучаются контракты и доступные требования.
- Публичные интерфейсы и форматы не меняются локально.
- Изменения в TЗ и планах задач не вносятся.
- При противоречии разработка останавливается и проблема фиксируется в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
- Существующий каркас и стиль сохраняются.
- Изменения тестируются в рамках Task ID.
- Любое изменение контракта согласуется командой.

Полный набор правил для ИИ-ассистентов приведён в [AI_DEVELOPMENT.md](AI_DEVELOPMENT.md).

## 8. Правила изменения контрактов

Изменение допускается только после:

1. определения затронутых модулей и форматов;
2. фиксации противоречия или новой потребности;
3. согласования с архитектором проекта;
4. обновления затронутых документов;
5. обновления тестов совместимости.

Изменения контрактов требуют согласования; открытые вопросы перечислены в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).
