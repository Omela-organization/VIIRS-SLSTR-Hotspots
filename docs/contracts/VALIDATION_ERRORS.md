# Ошибки валидации HS-01

`validate_detection_record()` возвращает `DetectionValidationResult`. Ошибки записи представлены объектами `ValidationIssue`; при передаче `QualityReport` они также агрегируются в `validation.errors`.

## Коды

| Код | Значение | Когда используется |
|---|---|---|
| `INVALID_INPUT` | Входное значение не является поддерживаемой записью | Вместо объекта передан, например, список или `null` |
| `MISSING_REQUIRED_FIELD` | Отсутствует обязательное поле | Pydantic сообщает тип `missing` |
| `INVALID_FIELD_TYPE` | Несовместимый тип или ошибка разбора значения | Тип ошибки Pydantic заканчивается на `_type` или `_parsing`; например, `datetime_type` |
| `VALUE_OUT_OF_RANGE` | Значение выходит за установленный диапазон или не является конечным числом | Нарушен числовой предел или получена ошибка `finite_number` |
| `INVALID_FIELD_VALUE` | Значение недопустимо по правилу поля | Например, неизвестная категория, некорректный WKB или не-UTC время |
| `UNEXPECTED_FIELD` | Передано неизвестное поле | Модель `DetectionRecord` запрещает дополнительные поля |

Код `code` стабилен и предназначен для программной обработки. Поле `type` содержит исходный тип ошибки Pydantic; его детализация может зависеть от версии Pydantic. `message` предназначено для диагностики и не должно использоваться как идентификатор ошибки.

## Поля ошибки

| Поле | Описание |
|---|---|
| `code` | стабильная категория из таблицы выше |
| `name` | человекочитаемое название категории |
| `field` | имя поля/путь или `null`, если ошибка относится ко всей записи |
| `type` | исходный тип ошибки Pydantic |
| `message` | описание причины |
| `severity` | `error` или `warning` |
| `can_continue` | для ошибки одной записи — `true`; обработка может пропустить запись и продолжить |

Сырые входные значения намеренно не входят в ошибку или JSON-отчёт.

## Правило продолжения

- Ошибка отдельной записи возвращается как `valid: false`, `record: null`; исключение Pydantic вызывающему коду не передаётся.
- Валидный результат содержит `record` и не содержит ошибок; невалидный результат не содержит `record` и включает хотя бы одну ошибку.
- В `errors` включаются все ошибки этой записи.
- `invalid_count` увеличивается один раз на невалидную запись, а не на каждое поле.
- Следующие записи можно проверять дальше.
- Ошибка сериализации или записи отчёта логируется и пробрасывается из `QualityReport.flush()`; её нельзя считать ошибкой отдельной записи или успешной обработкой.
