# Флаги качества

ТЗ v7 задаёт поле `flags` как одну маску `uint32` и перечисляет имена признаков в таблице 3.1. Модель HS-01 проверяет только диапазон целого числа; она не назначает биты и не интерпретирует их.

Предложенные номера битов ниже взяты из предшествующего интерфейсного документа. Они не являются утверждённой раскладкой. Точная семантика битов, их сочетания и влияние на пригодность остаются открытыми в CQ-04 и CQ-05.

## 1. Общие правила

- Битовая маска должна быть связана с логическим типом массива/поля `flags`.
- Возможность одновременного наличия нескольких флагов не уточнена ТЗ в доступных источниках.
- Маска пригодности и индивидуальные флаги качества являются разными понятиями: suitability определяется пригодностью пикселя, а флаги объясняют причины.
- Расширение набора флагов должно учитывать обратную совместимость и зарезервированные биты.

**Статус:** тип `uint32` подтверждён для таблицы обнаружений; семантика флагов и правила маски пригодности требуют согласования.

## 3. Правила чтения и установки

- Биты должны проверяться с помощью побитовых операций.
- Установка одного бита не должна обнулять остальные биты.
- Локальные несовместимые перечисления запрещены до согласования общей схемы.
- Зарезервированные биты не переиспользуются без нового соглашения.
- Модель HS-01 допускает любое значение в диапазоне uint32, но не проверяет сочетания отдельных флагов.
- Одновременное наличие нескольких флагов и влияние каждого из них на пригодность требуют согласования.

**Статус:** требуется решение по битам, сочетаниям и пригодности.

## 4. Расширение набора

Расширение набора флагов требует:

1. согласования имени и семантики;
2. согласования битовой позиции;
3. добавления модуля установки и модулей потребителей;
4. описания влияния на пригодность;
5. обновления тестов сериализации и чтения;
6. обновления схем форматов данных и CHANGELOG.
